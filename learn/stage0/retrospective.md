## 三问复盘（本人填写）

### 问题 1：这阶段最卡的一次排障是什么？最后怎么定位的？（写具体现象、你敲了什么命令、看了什么日志、结论是什么）

YAML 冒号连坏两次、VS Code 旧标签覆盖我改的文件、Docker 没启动、relation "users" does not exist、gh 令牌没权限。

以上大多由 AI 主导诊断、本人执行命令并验证——这是当前真实水平。印象最深一次：`docker compose up` 报 `volumes.pgdata must be a mapping`，反复改 yml 三次未修好，`docker compose config` 校验后由 AI 定位到 `pgdata:` 行被误改。结论：报错里的行号列号（L21.C3）就是现场；YAML 冒号与缩进是两大坑；AI 改过文件后 VS Code 旧标签不能再按保存。

**阶段 1 承诺：报错先自己读 + 排查 15 分钟再求助 AI（守则第 4 条）。**



### 问题 2：`docker compose down -v` 的 `-v` 删的是什么？删了会怎样？——用你自己的话解释

docker卷机制，数据其实住在卷里面，容器和网络删了后，卷的数据还在；所以如果要从根源上删除数据，就直接删卷上的数据，加-v;
