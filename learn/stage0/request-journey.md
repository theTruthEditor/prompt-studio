# 一次请求的完整链路 · 短文（出师标准②）

> 题目：用户在 Prompt Studio 页面点"保存提示词"，300ms 后列表里出现了新记录。
> **写出这 300ms 里发生的事**：从前端发出请求，一路追到 PostgreSQL 落盘，再返回渲染。
> 要求：500 字以内；成文必须自己写，卡壳可以问 AI 概念，但 AI 不代写。

## 必须覆盖的点（写完自查，每条都要在文中出现）

- [ ] 请求头里带的凭证是什么、放在哪里（JWT 放哪）
- [ ] 后端框架哪一层最先接住请求
- [ ] 参数校验发生在哪一步、校验失败返回什么
- [ ] SQL 是谁生成的（这个阶段：人写；阶段 1 之后：ORM 生成）
- [ ] 数据库连接是什么（TCP？连接池？谁建的连接）
- [ ] 这次写入有没有事务
- [ ] 响应状态码是什么、响应体大概长什么样
- [ ] 前端拿到响应后做了什么

## 正文（500 字以内）
请求头里面带的凭证是token、请求方法、请求文本类型等，放在哪里尚不清楚；后端框架应该是网络请求层先接住请求，
接到请求后，判断请求的类型后，找到对应的接口，再进行参数校验，校验失败的话返回404，sql是在逻辑代码中，已经
编写好的，通过sql生成，执行后对sql的结果同步到数据库，数据库连接使用的应该是连接池吧，连接方法由代码框架建立，
按道理写入之后，应该就算是执行成功，生成一条记录，不会有事物了，假设成功，响应的状态码是201，响应体大概有
{code:201,message:'新增成功'},然后返回对应的响应内容给前端。前端拿到响应后，假设成功，则刷新提示词列表信息，
以便给客户展示新增的提示词。

修订版：
前端点击生成提示词按钮，通过前端框架的封装的axios请求，将要保存的提示词内容通过接口发送请求，按钮loading展示；
axios请求中，需要携带与请求验证通讯的token，这个token是放在请求头的Authorization里面，是由后端校验用户信息之后
返回给前端的，前端会存储到storage或者浏览器自带数据库等。发送请求后，通过http请求层，后端会校验token是否合法，之后
会根据请求方法、类型找到后端代码中的相应接口进行验证，找不到的话，则返回404，找到了，参数错误，则返回400，如果参数完全
合法，则会执行后端对应接口进行的逻辑，有写好的sql语句，通过框架定制的长连接（有连接池等），接到对应数据库，执行对应的sql，
并返回结果到后端数据层。这次写入有事务，隐式事务肯定有，显式事务有几率发生，响应成功的话，会返回201，响应体是添加的提示词
json数据本体。前端拿到响应体之后，将返回的数据拼接到列表中，响应式刷新列表，loading效果停止。整个过程完成。
